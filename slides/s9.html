Cómo se implementa el diseño con Tailwind v4

Esta sesión no es "clases de Tailwind de memoria". Es entender el mecanismo: utilidades que se escriben directo en el HTML, cómo se configuran los tokens de color, y por qué el curso eligió Tailwind v4 (con Lightning CSS, sin autoprefixer).

PREGUNTA GUÍA: "¿Alguien ha escrito CSS en un archivo aparte y luego tenido que buscar la clase en medio de 500 líneas?" Anotar. Esa es la motivación de Tailwind: los estilos van donde el elemento. Nivel de entrada: saben CSS básico de S2. Nivel de salida: entienden utilidades, variantes responsive, tokens, y por qué v4 no necesita archivo de configuración JS.

Objetivos de la sesión

Al terminar vas a poder:

  1. Explicar qué es CSS utilitario y en qué se diferencia del CSS tradicional.
  2. Leer una clase de Tailwind (flex flex-col gap-4) y saber qué hace.
  3. Usar variantes responsive (md:, lg:) para mobile-first.
  4. Explicar por qué Tailwind v4 no usa tailwind.config.js ni autoprefixer en este curso.
  5. Leer el archivo global.css del sitio y reconocer los tokens de diseño.
Resaltar que hoy no van a construir una página entera: van a leer el diseño ya hecho en glud.org y entender cómo está implementado con Tailwind v4.

CSS tradicional vs utilitario

CSS tradicional

.btn-primary {
  background: #1affff;
  color: #111;
  padding: 1rem 2rem;
  border-radius: 8px;
}

Nombras la clase, escribes las reglas en un archivo aparte, y esperas acordarte del nombre cuando la uses.

Tailwind utilitario

<button class="bg-cyan text-support-eerie px-4 py-4 rounded-lg">

Escribes las reglas directamente en el elemento. No hay archivo aparte donde buscar "qué hace btn-primary".

Lego: el CSS tradicional es como armar un set siguiendo el manual paso a paso. Tailwind es tener todas las piezas sueltas en la mesa y armar lo que necesites con ellas. Más piezas visibles, pero más control directo.
Mostrar ambos ejemplos uno al lado del otro. El punto no es cuál es "mejor" en abstracto: es que Tailwind acopla diseño y estructura en un solo lugar, lo que acelera cambios y evita CSS muerto acumulado en archivos aparte.

Tailwind v4: lo que cambia

No hay tailwind.config.js ni autoprefixer

Tailwind v3Tailwind v4 (este curso)
Config en tailwind.config.jsTokens en @theme dentro de CSS (global.css)
Postcss + autoprefixer para compatibilidadLightning CSS integrado; sin autoprefixer (redundante, verificado A/B)
Colores en objeto JSVariables CSS nativas (--cyan, --purple)
La industria de hoy: Tailwind v4 es la versión actual del estándar de CSS utilitario. El equipo del GLUD verificó A/B que autoprefixer no aporta nada con Lightning CSS, por lo que lo eliminaron del stack. Menos dependencias, menos cosas que se rompen.
Explicar que v4 lee los tokens directamente de CSS, no de un archivo JS. Mostrar en el repositorio que no existe tailwind.config.js activo (o que está muerto) y que los colores viven en global.css bajo @layer base { :root { --cyan: ... } }. Conectar con S6 (pnpm) y S7 (Astro): el stack está intencionalmente ligero.

Tokens de diseño del sitio

Los colores no son capricho: viven en variables CSS

@layer base {
  :root {
    --cyan: #1affff;
    --purple: #7d1aff;
    --purple-bright: #b78bff;
    --orange: #fe9b1a;
    --pink: #ff5280;
    --bg-black: #1c1e1e;
    --white: #ededed;
    --support-grey: #8e95a1;
    --support-eerie: #111827;
    /* ... más tokens */
  }
}

Cuando el diseño dice "usa cian", el código usa var(--cyan) o la utilidad de Tailwind mapeada a esa variable. Cambiar el token cambia todo el sitio.

Conectar con S2: los tokens son la materialización de la paleta que se enseña ahí. Mostrar cómo global.css define el tema y cómo los componentes lo usan. Señalar que no hay colores hardcodeados sueltos en los componentes (salvo deuda identificada en el estudio de cumplimiento).

Responsive: mobile-first con variantes

Diseñas para el celular primero

<div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4">
  • grid-cols-1: aplica siempre (base móvil).
    • md:grid-cols-2: solo a partir de pantallas medianas.
  • lg:grid-cols-3: solo a partir de pantallas grandes. El móvil nunca carga estilos de escritorio que no necesita.
Empaque: diseñas la caja para que quepa en la mochila (móvil). Si el usuario tiene una maleta grande (escritorio), le agregas más compartimentos. Nunca al revés.
Explicar el prefijo md:, lg: como "a partir de este ancho". Mobile-first significa que lo que escribes sin prefijo es para móviles, y agregas capas para pantallas más grandes. Conectar con S3 (mobile-first es principio de diseño, ahora es implementación).

Cierre

Lo que se llevan

Tailwind v4 no es un lenguaje nuevo: es una forma de escribir CSS donde las utilidades van en el HTML, los tokens viven en variables CSS, y el responsive es mobile-first por defecto.

Una frase para llevarse: el diseño no vive en un archivo CSS aparte; vive en las clases de cada elemento, con tokens nombrados que cualquier miembro del equipo puede leer.
