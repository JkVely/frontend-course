S4 — JavaScript desde DevTools

Abre glud.org, presiona F12, pestaña Consola, y escribe:

document.title = "Tú mandas"

La pestaña cambió de nombre. Ningún programa externo hizo eso: lo ejecutaste tú, dentro del navegador. Hoy aprendemos a usar ese poder con intención.

PREGUNTA GUÍA: mostrar el poder inmediato de JS en el navegador. Pedir a un voluntario que ejecute el ejemplo y observe el cambio en la pestaña. Enfatizar que JS corre en la máquina del visitante, no en el servidor. Esto establece el tono de laboratorio: el navegador es el IDE. No se necesita instalar nada; todo se prueba al momento. Qué es JavaScript y dónde corre

JavaScript en el navegador del visitante

ConceptoQué esAnalogía
ExpresiónCódigo que produce un valorUna pregunta que el motor responde
SentenciaUna orden que hace algo (document.title = ...)Una instrucción que das al navegador
DeclaraciónDarle nombre a un valor (const nombre = "GLUD")Poner una etiqueta a un objeto

El motor JS interpreta todo en la máquina de quien visita. Por eso "poco JavaScript" significa "página más rápida": el visitante no tiene que descargar ni ejecutar tanto.

Explicar la distinción entre expresión, sentencia y declaración usando ejemplos simples. Subrayar que la ejecución ocurre en el cliente, lo que implica responsabilidad de desempeño y seguridad. Analogía con la redstone de Minecraft: la lógica se calcula en la propia máquina del jugador, no en un servidor central.

Consola como laboratorio

La Consola de DevTools como REPL

Abre cualquier página, pulsa F12 → Consola, y escribe:

2 + 3
typeof "GLUD"
typeof 42
document.body.innerText
document.body.children.length

La Consola es un REPL: lee, evalúa, imprime, repite.

Demostrar en vivo: abrir DevTools en glud.org, escribir cada línea y mostrar resultados. Resaltar que se pueden guardar valores en variables temporales (let x = 5) y reutilizarlos. Enfatizar que la consola permite experimentar sin recargar la página. Mencionar que el historial se puede usar con flechas arriba/abajo.

Paralelo Minecraft

JavaScript es tu redstone

La redstone en tu mundo: cuando pisas una placa de presión y la puerta se abre, eso no pasa en el servidor de Mojang — tu PC calcula esa lógica. JavaScript es tu redstone: cablea eventos dentro del navegador del visitante.
Desarrollar la analogía: en Minecraft, la redstone permite crear circuitos que responden a entradas del jugador y cambian el mundo localmente. De la misma forma, JS permite que la página responda a clics, teclas, movimientos del mouse sin necesidad de comunicarse con un servidor para cada acción. Esto permite interacciones instantáneas y experiencias fluidas.

Funciones: empaquetar decisiones

Entrada → decisión → salida

function saludar(nombre) {
  return "Hola, " + nombre + ", ¿cómo va tu curso?"
}
saludar("Mónica")

Versión moderna:

const despedirse = (nombre) => "Chao, " + nombre

Regla mnemotécnica: entrada → decisión → salida. Si no tiene return, no devuelve nada.

Explicar la estructura de una función: parámetros (entrada), lógica interna (decisiones), y valor de retorno (salida). Mostrar la diferencia entre la sintaxis tradicional y la función flecha. Enfatizar que una función sin return devuelve undefined implícitamente.

Ejercicio funciones en clase

EN CLASE (7 min):
  1. Copia y ejecuta esta función en la Consola: 
    function formatearNombre(nombre) {
  const limpio = nombre.trim()
  return limpio.charAt(0).toUpperCase() + limpio.slice(1)
}
console.log(formatearNombre("  daniela "))
console.log(formatearNombre("  MÓNICA "))
  2. Observa la salida. Actividad: corrige la función para que el resultado sea siempre capitalizado correctamente (primer letra mayúscula, resto minúscula). Comparte la solución.
Guiar a los estudiantes a probar la función, notar que actualmente solo capitaliza la primera letra pero deja el resto como estaba (ej. "daniela" -> "Daniela", "MÓNICA" -> "MÓNICA"). Proponer usar toLowerCase() en el resto de la cadena. Discutir variantes y permitir que compartan sus soluciones en el chat.

El DOM: cómo JavaScript toca la página

Accediendo y modificando elementos

const titulo = document.querySelector("h1")
const botones = document.querySelectorAll("button")

console.log(titulo.innerText)
titulo.innerText = "Cursos del GLUD"
titulo.style.color = "#1affff"
titulo.classList.add("grande")

querySelector devuelve el primer elemento. Si necesitas todos, usa querySelectorAll.

Explicar que el DOM representa la página como un árbol de objetos. Mostrar cómo querySelector selecciona por selector CSS y devuelve un nodo. Demostrar en vivo modificando el h1 de glud.org, cambiando texto, color y agregando una clase. Resaltar que los cambios se ven instantáneamente sin recargar.

Eventos

Escuchando acciones del usuario

const burger = document.querySelector(".menu-toggle")
burger.addEventListener("click", () => {
  console.log("Click")
  document.body.classList.toggle("menu-abierto")
})

Patrón: elemento → tipo de evento → función a ejecutar.

Ejercicio contador de clics

EN CLASE (10 min):

    let totalClics = 0
document.addEventListener("click", () => {
  totalClics++
  console.log(`Clic número ${totalClics}`)
})
  2. Cambia el evento a "mouseover" y observa cómo cambia el comportamiento.
