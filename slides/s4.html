S4 — JavaScript desde DevTools

Abre glud.org, presiona F12, pestaña Consola, y escribe:

La pestaña cambió de nombre. Ningún programa externo hizo eso: lo ejecutaste tú, dentro del navegador. Hoy aprendemos a usar ese poder con intención.

Java vs JavaScript

Comparando Java y JavaScript

Java

public class Saludo {
  public static String saludar(String nombre) {
    return "Hola, " + nombre;
  }
  public static void main(String[] args) {
    System.out.println(saludar("Mónica"));
  }
}

JavaScript

function saludar(nombre) {
  return "Hola, " + nombre;
}
console.log(saludar("Mónica"));
AspectoJavaJavaScript
TiposEstáticos al compilarDinámicos al ejecutar

Señalar que el nombre JavaScript fue estrategia de marketing de Netscape para aprovechar la popularidad de Java, aunque no tienen relación técnica. Destacar que Java requiere más código estructurado mientras que JS permite escribir menos líneas para lograr lo mismo. Preguntar: ¿qué implica que los tipos sean dinámicos? Esperar respuestas sobre flexibilidad y posibles errores en tiempo de ejecución.

Consola como laboratorio

REPL: el ciclo de ida y vuelta

REPL son las siglas de Read, Evaluate, Print, Loop: leer, evaluar, imprimir, repetir.

Readescribes una línea
→
Evaluateel motor la ejecuta
→
Printte muestra el resultado
→
Loopvuelve a empezar

La Consola es un ciclo de ida y vuelta, no un archivo que se compila. Pruébalo: escribe 2 + 3 en F12 → Consola.

Demostrar el ciclo en vivo: escribir 2 + 3 en la Consola y señalar cada paso del diagrama en voz alta: lo escribiste (Read), el motor lo ejecutó (Evaluate), te mostró 5 (Print) y quedó esperando la siguiente línea (Loop). Contrastar con el flujo de Java que ya conocen: allá se escribe el archivo completo, se compila y se ejecuta; acá el ciclo es línea por línea e inmediato. Mencionar que el historial se recorre con flechas arriba y abajo.

Tipos de datos y variables

const vs let

const persona = { nombre: "Ana", edad: 30 };
persona.edad = 31; // permitido: mutar propiedad
// persona = {}; // Error: no se puede reasignar

const impide reasignar la variable, pero si el valor es un objeto o arreglo, sus propiedades o elementos pueden modificarse.

Explicar la diferencia entre vinculación inmutable (const) y mutabilidad interna del objeto. Mostrar que intentar reasignar const lanza TypeError. Preguntar: ¿cuándo usar const y cuándo let? Esperar respuestas: const para valores que no se reasignan, let cuando el valor cambia.

Tipos de datos y variables

Coerción y comparación

"5" + 3   // "53"
"5" - 3   // 2
5 == "5"  // true
5 === "5" // false

Regla en grande: USA SIEMPRE ===.

Explicar que + con cadena convierte el número a cadena y concatena; - convierte la cadena a número y resta. == convierte tipos antes de comparar (coerción), mientras que === compara valor y tipo sin convertir. Destacar que usar === evita sorpresas. Preguntar: ¿qué resultados darían 0 == false y 0 === false? Esperar: true con ==, false con ===.

Qué es el DOM

DOM (Document Object Model)

El navegador lee tu HTML y construye un árbol de objetos; JS lee y modifica ese árbol y la pantalla se actualiza.

<html>
  <head>
    <title>Ejemplo</title>
  </head>
  <body>
    <h1>Título</h1>
    <p>Texto</p>
    <a href="#">Enlace</a>
  </body>
</html>
html

body
h1
Título
p
Texto

Enlace
Explicar que el DOM es una representación en memoria del documento HTML. Cada elemento es un objeto con propiedades y métodos. Cuando JS modifica ese árbol, el navegador vuelve a pintar la pantalla. Preguntar: ¿qué ventajas tiene separar estructura (HTML), presentación (CSS) y comportamiento (JS) mediante el DOM? Esperar respuestas sobre mantenibilidad y separación de preocupaciones.

El DOM

Acceder y modificar elementos

Explicar que querySelector devuelve el primer elemento que coincide con el selector, permitiendo acceder a sus propiedades y métodos. Mostrar cómo leer su contenido textual y atributos. Señalar que si no hay coincidencia devuelve null.

El Paradigma

El navegador espera

[Usuario hace clic]
→
[Navegador dispara "click"]
→
[Tu función corre]
→
[El DOM cambia]
→
[Navegador repinta]
Explicar que el sitio web no es un programa que se ejecuta de inicio a fin y termina; el código registra funciones y termina. Cuando el usuario interactúa, el navegador llama a esas funciones. Este modelo se llama programación dirigida por eventos. Preguntar: ¿qué pasa si olvidamos registrar un listener? Esperar que respondan que no ocurre nada. Señalar que el navegador mantiene un loop de eventos.

El Paradigma

Funciones de primera clase

const avisar = () => console.log("Me hicieron clic")
boton.addEventListener("click", avisar)

Frase clave: "avisar entra a addEventListener igual que un número entra a una suma; por eso ves funciones dentro de funciones en todo JS".

Destacar que en JS las funciones son valores que pueden guardarse en variables, pasarse como argumentos y retornarse. Contrastar con Java donde los métodos están ligados a clases y se pasa por referencia pero no se trata igual que datos primitivos. Preguntar: ¿qué ventajas ve al poder pasar una función como argumento? Esperar respuestas sobre callbacks, higher‑order functions, etc.

Eventos

Escuchando acciones del usuario

const burger = document.querySelector(".menu-toggle")
burger.addEventListener("click", () => {
  console.log("Click")
  document.body.classList.toggle("menu-abierto")
})

Patrón: elemento → tipo de evento → función.

Explicar el flujo de eventos: el usuario realiza una acción, el navegador dispara un evento correspondiente y ejecuta la función registrada (callback). Mostrar cómo múltiples listeners pueden responder al mismo evento y cómo el objeto event brinda información detallada. Señalar que este modelo permite crear interfaces reactivas y dinámicas.

Flujo HTML/CSS/JS

Cómo trabajan juntos HTML, CSS y JS

HTML

Estructura, el esqueleto

CSS

Presentación, la ropa

JS

Comportamiento, la redstone

Puente classList en 3 pasos:
  1. JS: titulo.classList.add("activo")
  2. CSS: .activo { color: #9ece6a }
  3. El navegador repinta.
Explicar que JS no dibuja directamente en el lienzo; su rol es modificar el DOM (añadiendo, quitando clases, cambiando atributos). CSS reacciona a esos cambios mediante reglas que coinciden con los selectores. Preguntar: ¿qué pasaría si intentáramos cambiar el color directamente con style en lugar de usar una clase? Esperar que mencionen especificidad y mantenimiento.
