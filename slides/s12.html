Qué más existe: React, Three.js y el ecosistema

Han terminado de destripar glud.org con Astro. Esta sesión abre el mapa: qué hay más allá, para qué sirve cada herramienta del ecosistema moderno, y cómo decidir cuándo aprenderla sin caer en "usar todo porque está de moda".

PREGUNTA GUÍA: "Además de Astro, ¿qué herramientas o nombres han oído en el mundo del frontend?" Anotar sin juzgar: React, Vue, Next, Three.js, Tailwind, Vite, Zustand, etc. Nivel de entrada: han oído nombres sueltos. Nivel de salida: saben qué hace cada categoría de herramienta y cuándo (y cuándo no) aprenderla.

Objetivos de la sesión

Al terminar vas a poder:

  1. Explicar para qué sirve React y cuándo tiene sentido usarlo.
  2. Explicar para qué sirve Three.js y cuándo tiene sentido usarlo.
  3. Ubicar en el mapa: frameworks, librerías de UI, manejo de estado, build tools, herramientas de prueba.
  4. Decidir, con criterio, si una herramienta nueva vale la pena para un proyecto concreto.
Resaltar: esta sesión no enseña a usar React ni Three.js. Enseña a reconocerlos y a decidir si aplican. El curso termina con criterio, no con una lista de tecnologías memorizadas.

React: la librería de UI más usada

¿Qué hace y cuándo tiene sentido?

Qué hace

  • Crea componentes que se actualizan solos cuando cambian sus datos
  • Usa un DOM virtual para no volver a pintar todo en cada cambio
  • Tiene el ecosistema más grande de librerías listas

Cuándo tiene sentido

  • Dashboards, paneles de administración, redes sociales
  • Sitios con mucha interacción y estado de usuario (login, carrito, chat)
  • Cuando necesitas ecosistema y contratación fácil
La industria de hoy: React es el estándar para aplicaciones web complejas. Pero usarlo para una página informativa estática es como usar un tractor para ir a comprar el pan: funciona, pero es excesivo y lento para el caso.
Conectar con S7: React es para aplicaciones, Astro para sitios de contenido. Mostrar ejemplos concretos: Instagram o un banco online (React tiene sentido); glud.org o una landing de evento (React es excesivo).

Three.js: gráficos 3D en el navegador

WebGL sin escribir WebGL a mano

  • Three.js permite crear escenas 3D, cámaras, luces y objetos que corren en el navegador mediante WebGL.
    • Se usa para visualizaciones, configuradores de productos, mundos inmersivos, arte digital.
  • No es para páginas informativas: es pesado, requiere tarjeta gráfica y su accesibilidad es limitada.
    • Tiene sentido en portafolios de artistas, sitios de productos con vista 3D, o experiencias inmersivas.
Escultura: Three.js es como tener una impresora 3D en el navegador. Impresiona, pero no la usas para imprimir una carta.
Mostrar ejemplos reales de Three.js (sitios de portafolio, visualizaciones de datos 3D) y preguntar: "¿glud.org necesita algo en 3D? ¿Por qué no?" La respuesta esperada: no, porque su propósito es informar, no impresionar visualmente. Conectar con el criterio del curso: herramienta según el caso de uso.

Cómo elegir sin caer en la moda

Un filtro de cuatro preguntas

  1. ¿Qué problema tiene el usuario que resolver?
    2. Si la respuesta es "ver información", un SSG ligero alcanza.
  2. ¿Necesita estado de usuario (login, carrito, chat)?
    3. Si no, no necesitas React con manejo de estado complejo.
  3. ¿Cuánto pesa la herramienta para el visitante? Cada librería extra es descarga y batería del teléfono.
  4. ¿Quién lo va a mantener y por cuánto tiempo? Una herramienta de moda que nadie del equipo conoce es deuda futura.
Recorrer las cuatro preguntas aplicándolas a un caso imaginario del grupo (ej: "¿construimos el sistema de inscripción de cursos con React o seguimos con LimeSurvey?"). El objetivo: que salgan con un método de decisión, no con una respuesta cerrada para todo.

Ejercicio guiado

EN CLASE (10 min):
  1. Elegir un proyecto imaginario del GLUD (ej: un visor de campus en 3D, un panel de inscripción de cursos, una landing de evento).
  2. Responder las cuatro preguntas del filtro para ese proyecto.
  3. Elegir una herramienta del mapa y justificar por qué.
  4. Presentar en 1 minuto: proyecto, herramienta elegida, y la razón de producto (no de moda).
El profesor actúa como juez de "criterio vs moda". Si alguien dice "React porque todo el mundo lo usa", se le pide que responda la pregunta 3 (peso para el visitante) y 4 (quién lo mantiene). El objetivo es que la justificación sea de producto, no de tendencia.
